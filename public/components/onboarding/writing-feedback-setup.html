Criteria — the rows

Starting points only: rename, reweight, add, or remove them.

  • Organization — how the text is staged
  • Content — how accurately it covers the subject

Performance levels — the columns

Lab Reports Carry a Second Rubric

Review the writing and the engineering content separately

Answer Lab report assignment when you create or import one, and it carries two rubrics. Both are edited and approved on the same page and share one set of assignment details.

Writing rubric

How the report is written.

  • Structure and staging of the report
  • Accuracy and sufficiency of what is explained
  • Stance, hedging, and technicality

Technical rubric

The department's evaluation form for engineering content.

  • Method and experimental reasoning
  • Data, results, and their interpretation
  • Stated assumptions and limitations

It checks whether the report's reasoning is consistent, not whether results match theory. It can read text and tables, but not figures. When a figure is needed, it tells staff that it could not assess that point.

Reviewing Generated Feedback

Every comment points at an exact passage you can check

EngE-AI prepares the draft in the background and updates the page when it is ready. First, review Annotations: every comment names a rubric criterion and quotes the passage it discusses. Then select Next to review the Summary. If you edit the comments, EngE-AI updates the summary. Your final version is what the student receives.

Organization Developing
"The results are shown in Figure 2. The heat transfer coefficient dropped. We also measured pressure drop."

Three findings in sequence, with nothing stating how they relate. Signal which observation is the main result and which support it, so the reader knows what the section argues.

Interpersonal Positioning Proficient
"Fouling resistance typically increases asymptotically over the first year of service (Kern, 1965)."

"Typically" marks a tendency rather than a certainty, and the attribution shows where the claim comes from. Repeat this stance in the discussion, where several claims are stated flatly.

What else the review page gives you

  • Comments by purpose: see how organization, content, and reader awareness affect the writing.
  • Course definitions: connect feedback to terms students already know.
  • Relevant course materials: point students back to useful readings.
  • Suggested levels: staff-only guidance that students never see.
  • Full editing: students receive only your final version.

Every quotation is checked against the submission. If EngE-AI cannot point to the student's own words, it does not make that comment.

Approving and Releasing

Two separate decisions, both yours

Approving marks feedback as ready. Releasing sends it to the student. These are separate so you control when students receive feedback.

Approved

In your course the release card appears next with one Release to Canvas action, stating what the student will receive. It sends the student-facing PDF comment and, if you saved a staff-final assessment, the grade.

  • Students never see confidence scores, internal review flags, model details, or staff notes.
  • Release is blocked while a rubric has changed since generation.
  • Feedback is released once per submission; a correction means a new attempt.
  • Nothing is delivered automatically. Release is always an action you take.

Welcome to Writing Feedback!

Writing Feedback suggests comments based on an approved rubric and connects each comment to an exact passage in the student's work.

Who can use it: instructors and teaching assistants have the same access.

Getting writing in: create an assignment directly or import one from Canvas, then add submissions as text or documents.

Verify every submission: course staff confirm that the text in EngE-AI matches what the student submitted before generating feedback.

Importing from Canvas brings across the assignment description and, where the Canvas assignment has one, the rubric you authored there. A manual assignment takes a title, instructions, and an optional due date. Submissions arrive as pasted text or uploaded documents.

Assignment details and the rubric

The rubric page has three steps. 1 · Describe the assignment records what students must do and what matters for grading. 2 · Build the marking grid defines the criteria and levels. 3 · Approve it makes the rubric available for feedback generation.

The grid: criteria are rows and performance levels are columns. Each box explains what that level looks like and may include a point range. A rubric can have 1 to 10 criteria and 2 to 8 levels.

The starting criteria are Organization, Content, and Interpersonal Positioning. You can rename, reweight, add, or remove them. If you import a Canvas rubric, EngE-AI uses that rubric instead.

Points: give each criterion a weight. Space points evenly divides that weight across the levels and warns you if two levels would receive the same points.

The Fill again from instructions button suggests short descriptions for the rubric boxes. It does not change your weights or remove criteria.

Approval: saving and approving are separate actions. Feedback cannot be generated until course staff approve the rubric. You can revise it later; earlier feedback keeps the rubric version used to create it.

Lab reports

An assignment created as a Lab report assignment carries two rubrics: a Writing rubric for how the report is written, and a Technical rubric for the engineering content. Both are edited and approved on the rubric page, and they share the assignment details.

Consistency, not agreement. The technical rubric checks whether the report's reasoning holds together. It does not mark results wrong simply because they differ from theory, calculate corrected values, or redo the experiment.

Text and tables only. EngE-AI cannot read figures, graphs, or images. If feedback would require one, it tells staff what it could not assess instead of guessing.

Review happens in two steps. First check the Technical and Writing comments. Then select Next. If you changed comments, EngE-AI updates the summary and suggested levels before you approve them.

Technical feedback cannot be edited on the review page. To change what it assesses, edit and approve the technical rubric, then generate the feedback again.

Reviewing feedback

EngE-AI prepares the feedback in the background and updates the page when the draft is ready.

Each comment names its rubric criterion and quotes the exact passage it addresses. If EngE-AI cannot point to the student's own words, it does not make that comment.

Comments can link to course definitions and materials. Student writing is never added to or searched with the course-material library.

Suggested grading is a reading aid for course staff. A grade is released only from the staff-final assessment you save and approve.

You can rewrite, delete, or add comments. EngE-AI keeps a history of staff changes, and students receive only the final version you approve.

Approval and release

Approving marks feedback as finished. Releasing delivers it. They are separate so you can control timing.

Press Approve to continue. Nothing is saved — this is a fixed example.

Students never receive confidence scores, internal review notes, system details, or staff-only comments. A numeric grade can be released only when every rubric level has a complete point value.

One release per submission. Release to Canvas sends the approved feedback once. To correct released feedback, create a new attempt. If the rubric changed after feedback was generated, generate it again before release.
